# Typography — universal font and type rules

Everything in the product is set in one typeface, Inter, and every size, weight,
line-height and letter-spacing value comes from a design token — never typed as a raw
number in component CSS. This file lists the type rules every AI tool and every developer
must follow in HTML/CSS output for any portal, the one legacy exception that is tolerated
(EX-003), and the one place 10px text is legitimate. Where a value is still disputed
(see the registers at the bottom), this file encodes only the part nobody disputes.

**Source status:** the brand facts below are quoted from
`Office_Work/memory/brand.md` (read 2026-08-24). That file's move into this folder is
**pending decision D** — until Singh rules, `memory/brand.md` remains the live source and
this file cites it rather than replacing it. Same pattern as iconography.

**Supersession:** for typography, this file supersedes the overlapping one-liners in
`Office_Work/ECOSYSTEM-RULES.md` §10 ("No hardcoded values — colors, spacing, radius, type
all come from CSS variables/tokens. Match Figma variable names.") and
`Office_Work/MASTER-AI-INSTRUCTIONS.md` §3 ("no hardcoded values — tokens from Figma
variables only"). Those lines remain true; this file is their checkable form.

## The rules

### UIG-004 + UIG-074 — one family: Inter, bound through the token

- **ID:** UIG-004 · UIG-074 (kept from SPEC-07 for traceability)
- **Plain-language summary:** every piece of text in every portal is Inter, and the CSS
  says so through the font token, never by typing the font name per component.
- **Assertion:** every `font-family` declaration outside `:root` resolves to
  Figma `font-family/primary` → `var(--font-family-primary)`; the rendered family is Inter.
  No secondary family anywhere, in any portal.
- **How a script tests it:** in stripped CSS, every `font-family:` value outside `:root`
  must match `var(--font-family-primary` (a real-font fallback stack after the var is
  permitted); computed style of rendered text resolves to `Inter`. Zero matches for any
  other family name — with exactly one carve-out: the EX-003 scope below.
- **Severity:** BLOCK
- **Source:** SPEC-07 §G UIG-004 ("No raw `font-family` outside `:root`", line 796) and
  UIG-074 ("Inter loaded", line 885); `memory/brand.md` lines 3–6 ("**Inter** — single
  family across entire product, all 4 portals … No secondary fonts allowed");
  `tokens.css` line 139.
- **The one tolerated exception:** **EX-003** — legacy `SF Pro Text` in Agency
  `Heading/H4 Headline`, pending removal in Figma. See `EXCEPTIONS.md`; do not widen it.

```css
/* WRONG — raw family typed into a component */
.c360-td { font-family: "Inter", sans-serif; }   /* bypasses the token: unfixable per-mode, invisible to checkers */

/* CORRECT — table cell text (SPEC-08a §10 pattern) */
.c360-td {
  font-family: var(--font-family-primary), Inter, sans-serif; /* element: table data cell text; binds font-family/primary; Inter named only as the fallback stack behind the token */
}
```

### UIG-003 — numeric weights only through weight tokens

- **ID:** UIG-003 (kept from SPEC-07)
- **Plain-language summary:** never type 400/500/600 into component CSS — use the four
  named weight tokens, whose values were verified against the generated Agency token file.
- **Assertion:** no raw `font-weight` numeral outside `:root`. The verified weight tokens
  are: `font-weight/body-base` → `var(--font-weight-body-base)` = 400 ·
  `font-weight/body-strong` → `var(--font-weight-body-strong)` = 500 ·
  `font-weight/heading-base` → `var(--font-weight-heading-base)` = 500 ·
  `font-weight/heading-strong` → `var(--font-weight-heading-strong)` = 600
  (all four: `tokens.css` lines 150–153, verified 2026-08-24).
- **How a script tests it:** `font-weight:\s*(\d{3})` in stripped CSS (outside `:root`)
  → 0 matches (SPEC-07's own regex, line 795).
- **Severity:** BLOCK
- **Source:** SPEC-07 §G UIG-003 (line 795); `tokens.css` lines 150–153.

```css
/* WRONG — raw numeral */
.c360-th { font-weight: 500; }   /* the number is right today and untraceable tomorrow */

/* CORRECT — column header weight (SPEC-08b §5) */
.c360-th {
  font-weight: var(--font-weight-heading-base); /* element: table column header; binds font-weight/heading-base = 500 (Inter Medium); no state variants — weight is constant across default/hover/sorted */
}
```

### UIG-071 — the 12px body-copy floor

- **ID:** UIG-071 (kept from SPEC-07)
- **Plain-language summary:** body copy is never smaller than 12px; the 10px `micro` size
  is banned in body copy with exactly one named exception.
- **Assertion:** `font-size/micro` (10px, `tokens.css` line 149) must not appear as a
  body-copy font size. Exactly one exception exists: **EX-002**
  (`.section__attribution`, the PRAPARE attribution line — see `EXCEPTIONS.md`). The
  exception is granted **by selector, never as a blanket size waiver**. 10px inside the
  tag component is a separate, legitimate case — see UHR-132.
- **How a script tests it:** no computed body-copy font-size below 12px; `10px` /
  `var(--font-size-micro)` appears only on the EX-002 selector and inside the tag
  component's `Label/overline` style (UHR-132 scope).
- **Severity:** BLOCK
- **Source:** SPEC-07 §G UIG-071 (line 882) and §H H-16 (Singh resolution 2026-08-17,
  line 919); OPEN-REGISTER A-3; EXCEPTIONS EX-002.

### UHR-131 — use the verified named text styles, not ad-hoc combinations

- **ID:** UHR-131 (new)
- **Plain-language summary:** for table, field and tag text, use the named Figma text
  styles below exactly as verified — don't assemble your own size/weight/line-height mix.
- **Assertion:** the adversarially verified named styles are:

  | Figma text style | Family / weight | Size / line-height | Tracking | Case | Verified in |
  |---|---|---|---|---|---|
  | `Table/header` | Inter Medium — `font-weight/heading-base` 500 | `font-size/caption` 12 / `line-height/caption` 16 | `fonts/tracking/X-tracking-0` = 0 | as typed | SPEC-08b §5 lines 186–199; SPEC-08a §7 line 288 |
  | `Table/value` | Inter Regular — `font-weight/body-base` 400 | 12 / 16 | 0 | as typed | SPEC-08b §5; SPEC-08a §7 line 289 |
  | `Fields/label` | Inter Medium — `font-weight/body-strong` 500 | 12 / 16 | 0 | as typed | SPEC-12 lines 84, 385; SPEC-07 §B.1 line 135 |
  | `Fields/value` | Inter Regular — `font-weight/body-base` 400 | 12 / 16 | 0 | as typed | SPEC-08a §7 line 290; SPEC-12 line 386 |
  | `Label/overline` (tags only) | Inter Semi Bold — `font-weight/heading-strong` 600 | `font-size/micro` 10 / `line-height/micro` 14 | 0 | **UPPERCASE** | SPEC-08a §5 lines 141–150 and §7 line 291 |

  Every property of these styles binds through the tokens in the quoted-values table
  above. Note `Fields/label` is Medium via `font-weight/body-strong` (500), not
  `heading-base` — same numeral, different token; bind the one the spec names.
- **How a script tests it:** for elements carrying these roles (table header/value cells,
  field labels/values, tag labels), computed font properties equal the row above and the
  declarations resolve through the named custom properties, not literals.
- **Severity:** WARN (BLOCK once Singh ratifies this file — the styles are verified for
  the Agency table/field/tag anatomy; coverage of other components is not yet assembled)
- **Source:** SPEC-08a §7 (lines 284–306), SPEC-08b §5 (lines 180–203),
  SPEC-12 (lines 84, 385–387); all in `Office_Work/Wound Management/05-Specs/components/`.

### UHR-132 — 10px is legitimate ONLY inside the tag component (`Label/overline`)

- **ID:** UHR-132 (new)
- **Plain-language summary:** the tag/status label really is 10px in the design system —
  that's allowed inside the tag component and nowhere else.
- **Assertion:** `Label/overline` (Inter Semi Bold 600, 10px, `line-height/micro` 14px,
  UPPERCASE) applies **only within the tag component**. This does not violate the UIG-071
  floor because the floor governs **body copy** — running text a user reads — while the
  tag label is a component-internal micro-label, verified as an authored Figma text style
  (`Label/overline`) on the tag anatomy, not an ad-hoc shrink of body text. Outside the
  tag component, 10px stays banned (UIG-071), except EX-002.
- **How a script tests it:** every occurrence of `var(--font-size-micro)` / computed 10px
  is inside a tag-component selector or the EX-002 selector; anything else fails UIG-071.
- **Severity:** BLOCK
- **Source:** SPEC-08a §5 lines 141–150 ("Inter Semi Bold 10px UPPERCASE … ✅ CONFIRMED
  … Figma style `Label/overline`", including the verifier's own completeness note adding
  `line-height: var(--line-height-micro, 14px)`) and §7 line 291; SPEC-07 H-16 for the
  floor's scope.

```css
/* WRONG — micro size leaking into body copy */
.f-msg { font-size: var(--font-size-micro); }   /* helper text is body copy: 12px floor applies (UIG-071, Singh 2026-08-17) */

/* CORRECT — tag label only (SPEC-08a §10 pattern) */
.c360-tag__label {
  font-family: var(--font-family-primary), Inter, sans-serif; /* element: status-tag label inside the tag component; binds font-family/primary */
  font-weight: var(--font-weight-heading-strong);             /* binds font-weight/heading-strong = 600 (Semi Bold) */
  font-size: var(--font-size-micro);                          /* binds font-size/micro = 10px — legitimate ONLY here (UHR-132) */
  line-height: var(--line-height-micro);                      /* binds line-height/micro = 14px */
  text-transform: uppercase;                                  /* the ONE verified transform in the system — authored in the Label/overline style itself */
}
```

### UHR-133 — case is content, not CSS: no blanket uppercase transforms

- **ID:** UHR-133 (new)
- **Plain-language summary:** text renders in the case it was written in — CSS never
  force-uppercases headers or body text; the only verified transform lives inside the tag.
- **Assertion:** no `text-transform: uppercase` in component CSS outside the tag
  component's `Label/overline` scope (UHR-132). Verified three independent ways on the
  canonical table header: Figma emits no `textCase`/`uppercase` on any header payload, the
  component set renders mixed-case literals, and real production usage renders Title Case
  (`City`, `Address`, `Zip Code`). **This rule deliberately says nothing about which
  casing the content strings themselves use** — the caps-vs-Title-case content dispute is
  **O-13** (OPEN, Wound Mgmt Q-B; also OVERRIDE-LEDGER row 14: wording is content →
  Aman's layer, type treatment is look → Figma's layer). Encode nothing on it.
- **How a script tests it:** `text-transform:\s*uppercase` in stripped CSS → matches only
  within tag-component selectors. The check asserts the treatment, never the string
  (exactly as `verify-ac-coverage.py` was corrected to do, ledger row 14).
- **Severity:** BLOCK
- **Source:** SPEC-08b §4 lines 125–141 ("Figma shows sentence / Title case. It does NOT
  show ALL CAPS … CSS must NOT set `text-transform: uppercase` on `th`");
  `Office_Work/Wound Management/00-OVERRIDE-LEDGER.md` row 14; OPEN-REGISTER O-13.

```css
/* WRONG — blanket transform on headers */
th { text-transform: uppercase; letter-spacing: .4px; }   /* the exact v1 defect corrected in ledger row 14 */

/* CORRECT — header text renders as authored */
.c360-th__title {
  font-weight: var(--font-weight-heading-base); /* element: header title text; binds font-weight/heading-base = 500 */
  /* no text-transform: case travels with the authored content string (UHR-133; content casing itself is O-13, undecided) */
}
```

### UHR-134 — letter-spacing: tracking 0 on the verified UI text styles

- **ID:** UHR-134 (new)
- **Plain-language summary:** table, field and tag text has zero letter-spacing — bound
  through the tracking token, never typed as a raw non-zero number.
- **Assertion:** the five UHR-131 styles all carry `fonts/tracking/X-tracking-0` = 0 →
  `var(--fonts-tracking-x-tracking-0)` ("All three roles use **one** family and **one**
  tracking. No letter-spacing anywhere." — SPEC-08a §7, scoped to those roles). A raw
  non-zero `letter-spacing` on any of these styles is a defect (v1's `0.4px` was exactly
  this, ledger row 14). **Scope note:** this is NOT a blanket "tracking 0 everywhere" —
  the Agency export separately defines `letter-spacing/heading` = -0.24px
  (`tokens.css` line 163) for heading styles; heading tracking is outside this rule.
- **Recorded gap:** `--fonts-tracking-x-tracking-0` is **absent from the generated Agency
  token file** (`tokens.css` lines 139–172 contain no tracking token; verified by direct
  read 2026-08-24), while the verified specs bind it with an explicit `0px` fallback
  (SPEC-08a §7 line 306; SPEC-08b line 566). Because the value is 0, the omission is
  visually safe — `var(--fonts-tracking-x-tracking-0, 0px)` renders identically either
  way. Flagged for the token-export lane to add the name; not a blocker.
- **How a script tests it:** on the five UHR-131 styles, `letter-spacing` is either
  absent (computed `normal`/0) or `var(--fonts-tracking-x-tracking-0` with a `0`/`0px`
  fallback; any raw non-zero value fails.
- **Severity:** BLOCK (on the five verified styles); the gap note itself is INFO.
- **Source:** SPEC-08a §7 lines 284–306; SPEC-08b §5 lines 195–196 and line 566;
  OVERRIDE-LEDGER row 14; `tokens.css` lines 139–172 (absence) and 163
  (`--letter-spacing-heading`).

```css
/* WRONG — invented tracking on table text */
.c360-th { letter-spacing: 0.4px; }   /* the v1 defect: no source anywhere gives table text non-zero tracking */

/* CORRECT — tracking bound through the token, safe fallback for the recorded export gap */
.c360-td {
  letter-spacing: var(--fonts-tracking-x-tracking-0, 0px); /* element: table cell text; binds fonts/tracking/X-tracking-0 = 0; 0px fallback covers the token's recorded absence from the Agency export (UHR-134 gap note) */
}
```

### UHR-135 — type colour: brand blue only through tokens, never as hex

- **ID:** UHR-135 (new)
- **Plain-language summary:** brand blue is locked by evidence and lives in the colour
  tokens — type CSS never spells out its hex value.
- **Assertion:** text/link colour binds semantic colour tokens — e.g. Figma `text/brand`
  → `var(--text-brand)`, `action/primary/bg` → `var(--action-primary-bg)` — and the brand
  primary's value is owned by the token layer, not by type rules. The value itself
  (`#0077FF`) is **evidence-locked** by CONTRADICTIONS **C2** (RULED: epic Rule 3 locks
  Brandblue; `memory/brand.md` lines 8–12: "This is NOT Tailwind blue — devs must use the
  custom token"). Raw hex may appear in quoted evidence and token definitions only.
- **How a script tests it:** case-insensitive `#0077ff` in stripped component CSS
  (outside `:root` token definitions) → 0 matches; brand-coloured text resolves through
  `var(--text-brand)` or another semantic `--action-*`/`--icon-brand` token.
- **Severity:** BLOCK
- **Source:** CONTRADICTIONS C2 (RULED); `memory/brand.md` lines 8–12; ECOSYSTEM-RULES
  §10 "No hardcoded values" (superseded by this checkable form); SPEC-08b §3 (link and
  help-marker bindings `text/brand` / `icon/brand`).

```css
/* WRONG — brand hex typed into type CSS */
.c360-td--link a { color: #0077FF; }   /* right value, wrong mechanism: invisible to colour modes and to checkers */

/* CORRECT — link cell text (SPEC-08b binding) */
.c360-td--link a {
  color: var(--text-brand); /* element: in-table link text; binds text/brand (brand primary, value owned by the token layer per C2); hover/visited states inherit the same token unless a spec names another */
}
```

## Per-portal notes

- **Agency:** carries the only tolerated family exception — **EX-003** (`SF Pro Text` in
  `Heading/H4 Headline`, pending removal in Figma; Design System Agents lane). The quoted
  token values above are from the **Agency** export (`tokens.css` is Agency-only by its
  own header, line 7–9); the family/weight/floor/case/tracking rules are universal.
- **All portals:** brand expression (Inter + brand blue) is portal-invariant —
  `memory/brand.md` "Brand Application Rules": semantic naming may differ per portal,
  brand expression stays consistent. Portal-specific token values must be re-verified
  against that portal's own export (e.g. `tokens-caregiver.css`) before being quoted.
- **Feature-parameterised sizes** (row heights, min-widths, paddings around text) are
  NOT typography rules — see SPEC-07 §G.2, feature-set values.
